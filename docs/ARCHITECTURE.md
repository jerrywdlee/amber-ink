# Architecture & Technical Design

## システム構成 (System Architecture)

本プロジェクトは、運用効率と開発スピードを重視し、**集約型アーキテクチャ (Aggregated / Fat Function)** を標準構成として採用しています。また、高度なスケーラビリティや独立性を必要とする環境向けに、**分散型構成 (Pure Microservices)** への切り替えも可能な柔軟な設計となっています。

### 主要コンポーネント (集約型 - デフォルト)
- **Frontend**: React (Vite) - 100% クライアントサイドでの暗号化・復号処理 (Web Crypto API)
- **Backend API**: Node.js (Google Cloud Functions) - ビジネスロジックの集約とデータ永続化の抽象化
- **Database**: MongoDB (Atlas/Container) - ペルソナ要約、ユーザーデータ、配信履歴の保存
- **AI Engine**: Google Gemini API (2.5-flash) - 高度な対話、感情解析、パーソナライズされたコンテンツ生成
- **Delivery Service**: Nodemailer / EJS - 感情に基づいたパーソナライズド・メール配信

## 環境変数・設定管理 (Configuration Management)
本プロジェクトは **Single Source of Truth（唯一の正）** 原則に基づき、すべてのバックエンド設定をプロジェクトルートの `.env` ファイルに集約しています。これにより、集約型・分散型のどちらのアーキテクチャにおいても、一貫した管理が可能です。

## データフロー

### 1. ペルソナ抽出・要約フロー
オンボーディングおよび日々の対話を通じて、AIがユーザーの「人となり」を抽出します。詳細は `SYSTEM_SUMMARY.md` を参照。
- **特徴**: PII（個人情報）を排除した「ペルソナ要約」のみを保持することで、プライバシー保護と文脈維持を両立。

### 2. 生存確認（チェックイン）
- **自動接続**: メール内のパーソナライズド・リンクをクリックするだけで、バックエンドで生存情報を更新し、ダッシュボードへリダイレクト。
- **不活動検知**: `EMERGENCY_THRESHOLD_DAYS` に基づき、一定期間アクティビティがないユーザーを自動抽出し、サポーターへ緊急連絡。

### 3. 「琥珀の宝石箱」セキュアプロトコル
- **クライアントサイド暗号化**: AES-256 (コンテンツ用) と RSA-2048 (鍵保護用) を組み合わせたエンベロープ暗号化。
- **ステガノグラフィ**: 秘密鍵を画像データ内に埋め込み、ユーザー自身が「鍵画像」として保管。サーバー側には秘密鍵を一切送信しない「ゼロ知識」型アプローチ。

## セキュリティ設計
- **ゼロトラスト・データ保護**: 重要メッセージはブラウザ外へ出す前に暗号化。
- **管理者保護**: `X-Admin-Token` ヘッダーによるバックエンド操作の認証。
- **PII-Free Prompting**: AI へのコンテキスト提供時に個人情報を厳格に排除。

## 技術的アピールポイント
- **スケーラビリティー**: ステートレスなバックエンド設計による、急激なユーザー増への対応。
- **高い移植性**: MongoDB インターフェースの抽象化により、Firestore 等への移行もスムーズ。
- **オフライン解凍**: 記念ページ（メモリアルエクスポート）は、サーバーが停止してもユーザー手元の鍵画像だけで想いを復元可能。
